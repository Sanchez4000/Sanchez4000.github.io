# Деплой

Как код попадает в опубликованное приложение.

## Что публикуется

Публикуется только клиентское приложение — как статический сайт на GitHub Pages.

Шлюз и бэкенд-сервисы в публикации не участвуют. Их развёртывание не автоматизировано.

## Рабочий процесс

Рабочий процесс GitHub Actions `static.yml` запускается при пуше в ветку `develop` и вручную из вкладки Actions.

Он выгружает содержимое `Frontend/Release/dist` как артефакт Pages и публикует его. Сборки в нём нет: ни установки зависимостей, ни вызова сборщика.

Одновременно выполняется одна публикация. Очередь схлопывается до последнего запуска, начатая публикация не прерывается.

## Билд в репозитории

Готовый билд клиента хранится в репозитории как обычные файлы — в каталоге `Frontend/Release/dist`. Рабочий процесс берёт оттуда то, что уже закоммичено.

Чтобы обновить опубликованную версию:

1. Собрать клиент локально командой `npm run build` в `Frontend/ClientApp`.
2. Перенести результат из `ClientApp/dist` в `Frontend/Release/dist`.
3. Закоммитить изменения и запушить в `develop`.

Шаги 1 и 2 выполняются вручную. Если их пропустить, публикация выложит прежнюю версию клиента.
