# Бэкенд-сервис: слоистая архитектура

## Идея

Каждый бэкенд-сервис — ASP.NET Core приложение, собранное по слоистой (Clean/Onion) архитектуре. Слои — это отдельные проекты внутри одного решения. Каждый слой отвечает за свою зону и не вмешивается в чужую.

Это единый архитектурный шаблон для всех бэкенд-сервисов репозитория. Новый сервис создаётся по тем же принципам, что описаны здесь.

## Слои и зависимости

Зависимости идут в одну сторону, сверху вниз:

```
          Api
       ↙       ↘
Application   Infrastructure
       ↘       ↙
          Domain
```

- **Domain** — модель предметной области. Сущности и правила, которые их касаются. Ни от кого не зависит.
- **Application** — бизнес-логика. Организована по CQRS: команды меняют состояние, запросы читают его. Зависит только от Domain.
- **Infrastructure** — технические детали: подключение конкретной СУБД, реализация внешних зависимостей, регистрация сервисов. Зависит только от Domain.
- **Api** — точка входа и composition root: HTTP-контроллеры, настройка приложения, сборка всех слоёв вместе. Зависит от всех остальных слоёв.

Такое разделение позволяет менять технические детали, например СУБД, не трогая бизнес-логику в Application.

## Технологии и соглашения

- ASP.NET Core — хост и HTTP-слой.
- HTTP-эндпоинты оформляются контроллерами, не Minimal API.
- Документация API — через OpenAPI, генерируется из контроллеров.
- Entity Framework Core + PostgreSQL — доступ к данным.
- CQRS-медиатор для организации бизнес-логики в Application.
- Обработка исключений — общая для всех сервисов, вынесена в `Backend/BuildingBlocks`. См. [Обработка исключений](exception-handling.md).

## Несколько сервисов, один шаблон

Сервисов несколько, у каждого — своя область ответственности и своя база данных. Общее у всех — только архитектурный шаблон и переиспользуемый сквозной код из `Backend/BuildingBlocks`. Бизнес-логика и модель данных у каждого сервиса свои.

`Api`-проект сервиса ссылается на `Backend/BuildingBlocks` через `ProjectReference`, как на любой другой общий проект репозитория.

## Состояние на сегодня

Медиатор для CQRS — MediatR. Новые версии MediatR стали платными. Планируется переход на бесплатную альтернативу. Выбор конкретной библиотеки уточняется.
