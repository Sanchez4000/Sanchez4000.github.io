# Архитектура

Состав системы и путь запроса через неё.

## Компоненты

| Компонент | Роль |
| --- | --- |
| Клиент | SPA в браузере. Единственный потребитель API |
| Шлюз | Единая точка входа. Пересылает запросы сервисам |
| Бэкенд-сервисы | Прикладная логика. Каждый отвечает за свою предметную область |

## Путь запроса

```
Клиент ──▶ Шлюз ──┬──▶ Сервис A
                  ├──▶ Сервис B
                  └──▶ Сервис N
```

Клиент обращается только к шлюзу и не знает адресов сервисов. Шлюз выбирает сервис по пути запроса, пересылает запрос и возвращает ответ клиенту.

Устройство маршрутизации описано в [API-шлюз](gateway.md).

## Границы компонентов

Сервисы независимы друг от друга. У каждого своё решение, свои зависимости и свой цикл сборки. Прямых вызовов между сервисами нет.

Общее у сервисов — сквозной код из `Backend/BuildingBlocks` и единый внутренний шаблон. Оба описаны в [Бэкенд-сервис](backend-service.md).

## Авторизация

Авторизацию выполняет сервис, а не шлюз. Требования к доступу у сервисов разные, и вынос проверки в шлюз заставил бы его знать о каждом из них.

Сейчас авторизации не требует ни один сервис.
