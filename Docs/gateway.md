# API-шлюз

Единая точка входа в систему. Расположен в `Backend/Gateway`.

## Назначение

Шлюз скрывает от клиента состав системы: сколько за ним стоит сервисов и по каким адресам они доступны. Клиент видит один адрес и один набор путей.

Шлюз намеренно тонкий. Он не разбирает тело запроса, не проверяет права и не хранит состояние. Сквозная логика остаётся на стороне сервисов.

## Технология

Шлюз построен на YARP (Yet Another Reverse Proxy) — библиотеке обратного прокси для ASP.NET Core.

Приложение состоит из одного проекта. Настройка сводится к двум шагам: прокси читает секцию `ReverseProxy` из конфигурации и подключается к обработке запросов. Кода маршрутизации в проекте нет.

## Маршрутизация

Конфигурация YARP описывается двумя сущностями.

| Сущность | Назначение |
| --- | --- |
| Маршрут (route) | Какие запросы принимать и как преобразовать перед пересылкой |
| Кластер (cluster) | Куда переслать запрос: один или несколько адресов сервиса |

Маршрут ссылается на кластер по идентификатору. Обе сущности описываются декларативно, в конфигурации приложения. Поэтому направления меняются и добавляются без правки кода и пересборки шлюза.

## Схема маршрута

Маршрут принимает запросы по префиксу с именем сервиса, снимает этот префикс и пересылает остаток пути на адрес кластера.

```
GET /example/api/v1/ping
        │
        ├─ маршрут:      /example/{**catch-all}
        ├─ преобразование: снять префикс /example
        └─ кластер:      http://localhost:5000
        │
        ▼
GET /api/v1/ping
```

Такая пара «маршрут — кластер» задана в конфигурации шлюза как образец. Сервис добавляется копированием этой пары с заменой префикса и адреса.
