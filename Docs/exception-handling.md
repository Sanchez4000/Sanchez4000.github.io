# Обработка исключений

## Идея

Каждый бэкенд-сервис приводит необработанные исключения к одному формату ответа. Логика этого приведения одна и та же для всех сервисов, поэтому она не пишется в каждом сервисе заново, а переиспользуется.

Переиспользуемая часть оформляется отдельно от конкретного сервиса — как отдельный проект, `Backend/BuildingBlocks`. Сервис ссылается на него и регистрирует обработку при старте, без копирования кода. Как именно сервисы ссылаются на общий код — см. [Бэкенд-сервис](backend-service.md).

Это часть сквозного слоя: то, что нужно каждому сервису одинаково, но не относится к его бизнес-логике. В будущем сюда же может переехать другая общая инфраструктура, не только обработка исключений.

## Механизм

Используется встроенный в ASP.NET Core механизм — `IExceptionHandler`. Он перехватывает необработанное исключение до того, как оно дойдёт до клиента как сырая ошибка сервера, и формирует ответ по единым правилам. Это заменяет `try/catch`, разбросанный по контроллерам.

## Формат ответа

Ответ — JSON-объект в формате ProblemDetails (RFC 7807), стандартном для ASP.NET Core. Клиент, сделавший запрос, получает читаемую структуру, а не голый текст исключения. Пример полей: код статуса, заголовок ошибки, описание.

Это открытый формат — клиент может разобрать его штатными средствами, без знания внутреннего устройства сервиса.

## Типизированные исключения

Разные ошибки должны получать разный статус ответа. "Не найдено" — не то же самое, что "нет доступа" или "некорректные данные".

Для этого используется иерархия исключений. Базовое исключение задаёт контракт: код статуса и заголовок ошибки. Каждый конкретный вид ошибки — свой класс-наследник со своим кодом и заголовком.

Обработчик проверяет одно: относится ли пойманное исключение к этой иерархии.

- Если да — это ожидаемая ошибка, осознанно выброшенная бизнес-логикой. Статус, заголовок и сообщение можно безопасно отдать клиенту.
- Если нет — это непредвиденная ошибка программы. Клиенту уходит общий безопасный текст и статус 500. Подробности пишутся только в лог.

Новый вид ошибки добавляется как новый класс-наследник. Сам обработчик при этом не меняется.

## Состояние на сегодня

Общая библиотека `Backend/BuildingBlocks` создана. В ней есть иерархия типизированных исключений, обработчик и способ подключить его в сервисе.

Подключать её пока не к чему — ни одного бэкенд-сервиса в репозитории ещё нет. Это будет первый шаг при создании первого сервиса.
